# Bonded Companions 技术规格

文档状态：v0.2 实现修订  
产品事实来源：PRD.md  
配方事实来源：RECIPES.md

## 1. 技术结论

采用“NeoForge 原生数据系统 + 每物种适配器 + 独立管理菜单 + 方块物流代理”的结构。基础模组只硬依赖 NeoForge；当前只维护用户明确指定的 Create、Carry On、Horseman、Modular Golems、Create: Meowchanics 与 Jade 软兼容，不为其他模组提前建立适配层。

最重要的边界是：

- Alt 只负责客户端表达用户意图，服务端重新验证并打开页面。
- 名单只由一个中央规则引擎判断，任何物种不得复制一套优先级。
- 生物装备不向自动化暴露；货运拴桩只代理货仓。
- 原版已有栏位复用原版真实物品，绝不再保存一份镜像。
- 狐狸攻击采用本模组自己的受控近战结算，避免伤害附魔或重锤逻辑绕过倍率。
- 不修改 Horseman 的菜单，也不把猫纳入 v1。

## 2. 固定环境

| 项目 | 基线 |
|---|---|
| Minecraft | 1.21.1 |
| Loader | NeoForge 21.1.x；目标整合包观察值 21.1.228 |
| Java | 21 |
| Mapping | 与目标 NeoForge MDK 一致 |
| Build | Gradle Wrapper，具体版本由 MDK 锁定 |
| Required dependency | NeoForge only |
| Optional compatibility | Create 6.0.10、Carry On 2.2.2.11、Horseman 1.5.9、Create: Meowchanics 2.0.4、Modular Golems 3.1.33、Jade |

不同时支持 Fabric、Forge 或其他 Minecraft 主版本；这会显著扩大事件、菜单、附魔和渲染差异，且对当前私用整合包没有产品价值。

## 3. 建议命名与模块

暂定 mod id：bonded_companions  
暂定 Java package：dev.dklon.bondedcompanions

代码按职责分组，而不是按“一个生物一个巨型类”分组：

| 模块 | 职责 |
|---|---|
| common.interaction | Alt 请求、实体局部命中、交互优先级 |
| common.menu | 管理菜单、装备槽验证、货仓槽 |
| common.ledger | 名单数据、录入 UI、目标规则引擎 |
| common.companion | 归属、模式、物种适配器、通用安全规则 |
| common.combat | 自定义伤害、减伤、致命保护、冷却 |
| common.equipment | 自定义栏位、属性、耐久与掉落 |
| common.enchantment | 专属附魔效果与互斥关系 |
| common.cargo | 货运物品内容、拴桩、过滤与红石 |
| client | 页面、模型层、键位、提示与粒子 |
| compat | 按 mod id 隔离的软兼容入口 |
| data | 配方、标签、附魔、战利品、交易与语言资源 |

CompanionSpeciesAdapter 是窄接口，负责声明某个物种有哪些栏位、允许什么物品、管理模式及物种特有行为。名单判断、网络验证、存储和通用伤害规则不得下沉到各适配器重复实现。

## 4. 数据模型

所有持久数据都带 schemaVersion。读取未知新版本时保持原物品或实体可加载，禁用无法理解的功能并给日志警告，不删除数据。

### 4.1 目标名单册组件

组件 ID：bonded_companions:target_ledger_data

TargetLedgerData：

| 字段 | 类型 | 含义 |
|---|---|---|
| schemaVersion | int | 数据迁移版本 |
| useDefaultBlacklist | boolean | 是否启用默认黑名单，默认 true |
| whitelist | list of TargetRule | 显式白名单 |
| blacklist | list of TargetRule | 显式黑名单 |

TargetRule：

| 字段 | 类型 | 约束 |
|---|---|---|
| subjectType | PLAYER / ENTITY_TYPE / NAMED_ENTITY | 必填 |
| registryId | resource location or absent | ENTITY_TYPE 与 NAMED_ENTITY 保存种类 |
| subjectUuid | UUID or absent | PLAYER 与 NAMED_ENTITY 必填 |
| nameSnapshot | text or absent | 只用于 UI，不参与稳定身份判断 |

保存时去重并限制单本名单最多 256 条显式规则（测试基线），防止损坏数据或恶意输入造成无界扫描。规则查找在组件加载后构建临时集合索引；索引不序列化。

### 4.2 伙伴实体附件

附件 ID：bonded_companions:companion_data

| 字段 | 含义 |
|---|---|
| schemaVersion | 数据版本 |
| ownerUuid | 新增可归属生物的主人；原版可驯服实体仍以原版 owner 为权威 |
| mode | FOLLOW、WAIT、GUARD、DIG 等物种允许模式 |
| customEquipment | 仅保存原版没有的装备位 |
| cooldowns | 以稳定 ID 记录不屈、归魂、回响等服务端游戏时间截止点 |
| flags | 一次性提示与物种状态，不保存客户端显示缓存 |

原则：

- 狼铠使用原版 BODY 物品槽。
- 狐衔使用狐狸真实主手物品。
- 马的鞍与马铠使用原版真实槽；马用驮箱替代鞍位时，该槽中的物品就是驮箱。
- 其余原版没有的栏位才进入 customEquipment。
- 冷却保存绝对服务端 gameTime 截止值，并在存档加载时安全钳制，换装备不能重置。
- 雪傀儡与铁傀儡虽然都使用 customEquipment 索引 2，但允许物品由各自的装备标签独立约束；共享栏位编号不代表装备可互换。

### 4.3 控制核心组件

组件 ID：bonded_companions:control_core_data

| 字段 | 含义 |
|---|---|
| schemaVersion | 数据版本 |
| ownerUuid | 核心主人 |
| boundGolemUuid | 当前绑定傀儡；傀儡死亡后清空 |
| dimension | 固定守卫中心所在维度 |
| center | 整数 X/Y/Z 中心 |
| radius | 8、16、24、32 或 48 |
| mode | GUARD、FOLLOW 或 STANDBY |

控制核心物品是傀儡范围与模式的唯一持久事实来源。companion_data 不复制 activityArea；实体只可缓存本 tick 的解析结果。移除核心后缓存立即失效并进入待命。

首次普通右击绑定时，服务端验证傀儡可绑定、核心未被另一个仍存活且已加载的傀儡占用，并写入 ownerUuid 与 boundGolemUuid。傀儡死亡掉落核心前清空 boundGolemUuid，但保留主人、中心、半径和模式，便于重用。

### 4.4 货运组件

组件 ID：bonded_companions:cargo_contents

| 字段 | 含义 |
|---|---|
| schemaVersion | 数据版本 |
| cargoType | SATCHEL、HORSE、DONKEY、MULE、CAMEL、STRIDER、SEED |
| size | 固定容量，必须与物品类型匹配 |
| stacks | 非空 ItemStack 的槽位映射 |
| filters | 骡的 3 个幽灵过滤项；其他类型为空 |

读取时不能相信序列化 size。实际容量由注册物品类型决定；越界物品进入恢复队列，在下次合法打开或实体加载时返还玩家/掉落，不能静默删除。

所有货运物品加入 bonded_companions:cargo_containers 标签。插入处理器拒绝该标签，阻止本模组容器互相嵌套。

### 4.5 美西螈装桶

美西螈进入桶时，将 `companion_data` 编码到原版 `BUCKET_ENTITY_DATA` 的本模组命名键下；放出时从同一载荷还原。原版 1.21.1 没有可覆盖这两个阶段的完整 NeoForge 事件，因此只在 `Axolotl.saveToBucketTag` 与 `loadFromBucketTag` 尾部使用版本锁定的最小 mixin。它不得取消或替换原版装桶、放出、音效、成就、变种及年龄处理。读取时按美西螈的两个合法栏位和允许模式再次净化数据，损坏载荷只记录警告并退回普通桶装美西螈。需要测试：

- 有主人/无主人。
- 有名单与背带。
- 背带带附魔和损耗。
- 冷却进行中。
- 发射器放出、玩家放出、跨维度携带。

若任何一项不能可靠往返，不能发布美西螈模块。

## 5. 名单规则引擎

### 5.1 单一判定函数

输入：攻击者伙伴、候选目标、已装备名单册、主人关系、当前模式。  
输出：ALLOW、DENY 或 VANILLA。

判定顺序：

1. 无名单册：VANILLA。
2. 候选无效、死亡、旁观、跨维度或物种无法到达：DENY。
3. 命中显式白名单：DENY。
4. 是主人、同主人伙伴或关闭友伤的同队成员：DENY。
5. 命中显式命名个体黑名单：ALLOW。
6. 命中显式种类/玩家黑名单：ALLOW。
7. 默认名单开启，且候选符合敌对判定或包含标签，并且不在默认排除标签：ALLOW。
8. 其他：VANILLA。

显式白名单检索同时检查玩家 UUID、命名实体 UUID 和种类；任一白规则命中即终止。显式黑名单只有在所有白规则都未命中后评估。

### 5.2 默认标签

至少提供：

- bonded_companions:default_blacklist_include
- bonded_companions:default_blacklist_exclude
- bonded_companions:neutral_mobs
- bonded_companions:catastrophic_targets

运行时默认黑判定为“实现敌对怪物语义或位于 include 标签”，再减去 exclude。蜘蛛与洞穴蜘蛛显式放入 include；末影人、猪灵系、监守者、凋灵和末影龙放入 exclude。任何显式黑名单规则仍可覆盖默认 exclude，白名单除外。

### 5.3 最后一层友伤保险

在伤害进入目标前再次调用关系判断。如果伤害来源可追溯到已归属伙伴、伙伴发射物、烬雪、荆棘或专属范围效果，并且受害者为白名单/主人，则取消伤害。

这一层不是替代 AI 正确选敌，而是防止投射物延迟命中、反伤和其他模组重定向目标时突破白名单。

## 6. 输入与网络契约

### 6.1 客户端输入

- 注册“Open Companion Management”键位，默认 Left Alt。
- 监听使用键触发；管理键按下且 Shift 未按下时，对准星实体执行客户端预检查。
- 预检查通过后取消这一次本模组管理交互并发送请求；预检查失败不取消原版右击。
- 不将“Alt 正在按下”作为实体同步状态，也不每 tick 发包。

### 6.2 服务端请求

OpenCompanionMenuRequest：

| 字段 | 类型 | 说明 |
|---|---|---|
| entityId | int | 客户端看到的目标实体 ID |
| hand | enum | 本次使用的手 |

服务端验证：

1. 玩家存活且不在旁观。
2. 实体存在、维度相同、距离不超过 5 格（测试基线）。
3. 服务端从玩家视线重新射线检测，命中实体必须与 entityId 一致或其包围盒相交。
4. 实体类型受支持。
5. 玩家是主人或满足该物种的合法绑定条件。
6. 玩家未按服务端可见的 Shift 状态；若按下则拒绝，让 Carry On 路径保持独立。
7. 每玩家打开请求有 5 tick 冷却（测试基线）。

通过后由服务端创建菜单并同步实体 ID。客户端永远不能要求直接写入某个槽或指定伤害目标。

### 6.3 其他请求

- CompanionActionRequest：抚摸、切换模式、设置中心。
- LedgerEditRequest：删除条目、切换默认名单；新增条目必须来自服务端验证过的实体交互。
- FilterEditRequest：只保存物品类型/标签样本，不移动真实物品。

每种请求都有菜单会话、所有权、距离、枚举值、槽位和值域验证。无效请求仅拒绝并限频记录，不因客户端错误让世界崩溃。

## 7. 菜单与装备

### 7.1 独立菜单

每个受支持类别注册自己的 AbstractContainerMenu 或共享布局驱动菜单。菜单只读取实体真实槽与附件槽，不复制 ItemStack。

必须实现：

- canUse 持续检查实体存活、距离与所有权。
- 槽验证与最大堆叠数 1 的装备位。
- 关闭菜单时光标物品按原版规则返还。
- 实体死亡/卸载时强制关闭会话并由服务端处理掉落。
- 快速移动使用明确的目标槽顺序，不依赖 Horseman 或原版菜单的数字索引。
- 共享菜单通过打开缓冲区只同步实体 ID 与物种枚举；客户端从当前世界解析实体模型，装备内容仍以服务端菜单槽同步为权威。
- 固定布局由“生物预览、归属/模式、物种装备位、玩家背包”四块组成。装备位数量和标签来自物种描述表，不使用 `GENERIC_9x1` 伪装。
- 空装备位由客户端渲染低亮度代表物品，标签区给出用途提示；槽本身仍由服务端规则决定可放物品。
- `stillValid` 每次检查存活、距离和 `isManageableBy`；附件 UUID、原版驯服标记和原版坐骑驯服标记必须同时满足各自物种条件。

### 7.2 马匹兼容策略

不修改 AbstractHorseMenu，也不向其注入槽。马、驴、骡、骆驼的本模组货仓使用独立菜单；Horseman 的栓绳栏位继续由 Horseman 自己管理。

马用驮箱占原版鞍位的实现要求：

- 扩展鞍位接受标签，使马用驮箱可放入，但骑乘检查只把原版鞍视为可骑。
- 若无法通过 NeoForge 事件/标签安全扩展原版槽验证，采用一个极小且版本锁定的访问转换或 mixin，只改变该物品的合法性，不替换整个菜单。
- 驮箱安装期间拒绝上马；拒绝逻辑在服务端执行。

### 7.3 局部命中

货仓只响应 EntityInteractSpecific 一类带命中位置的交互。把世界命中点转换到实体局部坐标，并按实体当前尺寸归一化：

- 马：上背部驮箱区域。
- 驴/骡：两侧驮具区域。
- 骆驼：背部商旅架区域。
- 炽足兽：两侧耐热驮袋区域。

阈值通过模型截图与游戏内射线测试冻结，不写死为只适用于成年默认尺寸的一组世界坐标。幼体不允许装备货运物品。

## 8. AI 与物种适配

### 8.1 调度

- 伙伴不在每 tick 对完整实体列表做搜索。
- 以实体 UUID 哈希错开，每 10 tick 执行一次候选扫描。
- 首先使用限定 AABB 获取候选，再用规则引擎和可达性过滤。
- 现有合法目标可在轻量 tick 中维护；白名单变化或模式变化立即失效缓存。

### 8.2 Goal 与 Brain 边界

- 狼、狐狸、铁傀儡、雪傀儡等 GoalSelector 生物：在实体加入世界时幂等地安装小型目标/返回目标，不覆盖整个原版目标选择器。
- 若 goalSelector 的可见性阻塞，优先使用 NeoForge Access Transformer；只有无法稳定转换的单一调用点才用 mixin。
- 山羊与嗅探兽等 Brain 驱动行为不强塞进 GoalSelector。使用物种控制器协调记忆、导航和专属动作，并尽量让原版 Brain 继续处理闲逛、避险与挖掘。
- 每次安装都带内部标记，区块重载不能重复添加目标。
- 狐狸在实体加入世界时移除只适用于野生个体的玩家躲避目标，并安装高优先级跟随与受控近战 Goal。归属成功时同时把主人加入狐狸信任列表，避免跟随与逃避在距离阈值处振荡。
- 自定义跟随 Goal 每次启动都重新读取 owner 和 mode，不缓存跨维度玩家对象；WAIT、GUARD、STANDBY、死亡和不同维度均立即停止。
- 受击防卫必须先调用中央名单规则。合法攻击者才可设为目标，白名单对象不会通过“复仇”绕过保护。

### 8.3 生存优先级

统一优先级为：

1. 致命保护/归魂等强制状态。
2. 缺氧、缺水、火、水和悬崖避险。
3. 等待、回到活动区、跟随主人。
4. 维持现有合法战斗。
5. 扫描新目标。
6. 原版闲置行为。

美西螈和海豚的水域可达性、山羊冲撞安全线、傀儡活动圆柱必须由各自适配器实现，但目标合法性仍调用中央规则引擎。

## 9. 战斗与附魔结算

### 9.1 通用顺序

所有数值使用浮点计算，只在 Minecraft 最终伤害流程需要时处理，不在每一步取整：

1. 验证攻击目标与白名单。
2. 计算攻击者基础伤害和合法装备属性。
3. 应用武器类别规则。
4. 应用追猎、伏袭、追香、破阵等本模组攻击修正。
5. 交给原版护甲、原版保护附魔与抗性处理。
6. 对剩余伤害应用忠卫、补强、堡垒等自定义减伤和各自上限。
7. 评估不屈、归魂等致命触发。
8. 结算耐久、冷却、治疗、战利品与经验。

### 9.2 狐狸受控近战

狐狸不能直接复用玩家武器攻击方法，因为它会把锋利、火焰附加、密度、破甲或重锤坠击带入结算。

实现定义：

- D 是狐狸基础攻击属性加持有物品提供的合法基础攻击属性，排除所有禁用伤害附魔与玩家专属攻击形态。
- 普通非专属武器：categoryDamage = D × 0.5。
- 原版重锤：categoryDamage = D × 0.7。
- 衔月刃：categoryDamage = foxBaseDamage + materialFoxBonus。
- 后续再乘伏袭、追香等专属效果。
- 重锤持有期间使用稳定属性 modifier，使最终移动速度乘 0.7；取下立刻移除，不能重复叠加。
- 重锤永远按地面普通近战处理，不读取狐狸摔落距离。
- 狐狸攻击后按物品规则损耗耐久；工具仅在作为允许的普通近战物品时损耗。

禁用伤害附魔采用数据标签加效果类别判断，不能只写一串原版附魔 ID，否则模组附魔可绕过。无法可靠分类的第三方附魔默认在狐衔中不执行主动伤害效果，保留物品本身数据。

### 9.3 属性与状态

- 所有装备属性 modifier 使用稳定且唯一的 ResourceLocation ID，装备重复同步不能叠层。
- 移速百分比按乘法总值处理；热行只把自己的 5%/10% 加值切换为 10%/20%，不翻倍基础速度。
- 最大生命装备卸下时只钳制当前生命，不造成一段额外伤害事件。
- 不屈和归魂冷却保存在实体附件，不保存在装备上。
- 狼自定义减伤上限 80%，铁傀儡本模组额外减伤上限 40%；原版护甲/保护先结算。

### 9.4 附魔互斥

使用 1.21 数据驱动附魔标签表达常规互斥，并在铁砧与加载时做第二次验证：

- 忠卫 ↔ 不屈。
- 堡垒 ↔ 应激甲片。
- 烬雪 ↔ 深寒。
- 骑手之盾 ↔ 弹射物保护。

非法数据的确定性规则：不屈优先于忠卫；应激甲片与堡垒同时存在时两者都停用并提示修复；烬雪优先于深寒；骑手之盾优先于弹射物保护的自定义骑手效果，但原物品不被删除。

原版 `AnimalArmorItem` 会硬性拒绝附魔台。为实现狼铠与马铠附魔，只在 `Item.isEnchantable` 和 `getEnchantmentValue` 上用物品身份受限的 mixin 放行狼铠及四种马铠；允许集合仍由 `minecraft:enchantable/*` 标签与各附魔的 `supported_items` 决定。狼铠加入 `armor`、`durability`、`equippable`，但不加入 `chest_armor`，因此可获得四类保护、耐久/经验修补、绑定/消失诅咒而不能获得荆棘。马铠只加入 `armor`，因此不获得耐久、经验修补、绑定或荆棘。

## 10. 货运与自动化

### 10.1 实体侧

货仓菜单直接操作已装备货运物品的 cargo_contents。不要给实体注册可被通用自动化发现的 ENTITY_AUTOMATION 物品接口；这可以阻止漏斗矿车或未知模组从任意位置抽取宠物装备。

### 10.2 货运拴桩方块实体

CargoHitchingPostBlockEntity 保存当前链接的实体 UUID 和短期解析缓存，不保存第二份物品。每次能力访问重新验证：

- 链接实体存在且存活。
- 仍由牵绳连接该拴桩。
- 距离不超过 2.5 格。
- 未被骑乘。
- 货运物品仍存在且类型合法。
- 拴桩未被红石锁定。

满足条件时，拴桩通过 Capabilities.ItemHandler.BLOCK 返回一个代理 IItemHandler。所有 insert/extract 的 simulate 与 execute 都在服务端完成；执行阶段再次校验链接和目标 ItemStack 身份，防止菜单拆下货具与漏斗传输同 tick 造成复制。

断开时使旧能力失效并通知邻接物流重新查询。旧代理即使被第三方缓存，后续操作也必须返回原物品而不能访问已拆下货仓。

### 10.3 骡过滤

- 自动插入时，若三个过滤位都空则全部接受。
- 任一过滤位有值时，物品满足至少一个过滤器才允许插入。
- 自动抽取不受过滤限制。
- 玩家手动菜单不受过滤限制。
- 过滤器比较默认使用物品类型；是否匹配组件/标签以后续 UI 明确选择为准，v1 不做复杂表达式。

### 10.4 Create 兼容

Create 的漏斗、溜槽和机械臂通过方块物品能力发现目标，因此只要拴桩正确提供 BLOCK item handler 即可集成。不要依赖 Portable Storage Interface：它面向 contraption，不是动物库存接口。

基础模组不引用 Create 类。可选 compat 模块只负责：

- 确认目标 Create 版本能发现标准能力。
- 为机械臂交互点或打包器添加必要的小型适配，前提是标准能力测试失败。
- 在 Create 缺失时完全不加载这些类。

## 11. 第三方兼容边界

本节是当前制作阶段唯一主动维护的第三方兼容清单。未列出的模组不做猜测性 hook、反射探测或专用配置；完整整合包测试若发现真实冲突，再建立独立问题与最小修复范围。

### 11.1 Carry On

- 本模组只在管理键按下且 Shift 未按下时工作。
- Shift + 右击路径不取消事件。
- Alt + Shift 不打开管理页。
- 集成测试覆盖空手、持名单册、持食物和持 Carry On 可抱取方块四种情况。

### 11.2 Horseman

- 不替换马菜单、不重排其槽位、不按数字访问其新增栓绳槽。
- 本模组的货仓为独立菜单。
- 若需要判断 Horseman 拴桩状态，只通过公开能力/接口或反射隔离的软兼容读取；读取失败则退回本模组货运拴桩逻辑。

### 11.3 Modular Golems

- 只增强原版 EntityType.IRON_GOLEM 与 EntityType.SNOW_GOLEM。
- 不给 Modular Golems 的自定义傀儡强行注入栏位或属性。
- 所有属性 modifier 使用本模组命名空间，避免与模块化装备同 ID。

### 11.4 Create: Meowchanics

- v1 不注册猫物种适配器，不添加猫菜单、猫装备或猫目标 Goal。
- 发现 mod id laowu 时不执行任何侵入式猫补丁。
- 未来只在出现稳定公开事件/API 后考虑“白名单否决”适配：允许名单阻止其职业 AI 攻击某对象，但不主动给猫注入新的黑名单攻击，也不绕过机械化进度。

## 12. 渲染与客户端

- `ART-DIRECTION.md` 是物品贴图、装备渲染层、配色和模型轮廓的视觉事实来源；现有生成图片与预览图不作为后续重制参考。
- 自定义装备使用独立实体渲染层，不替换整个原版模型。
- 狐衔直接渲染真实主手 ItemStack；衔月刃只需补正确的口部变换。
- 雪傀儡补强统一锚定在上下雪球连接处，正面为纽扣留出开口；其控制核心固定在上层雪球侧前方约 30°。铁傀儡补强统一锚定在躯干正面外围，为上胸中央控制核心留空，且不增加前臂或腿部附件。两条模型独立制作，均不得表现成完整盔甲套；铁傀儡铁、钻石、下界合金三级物品图沿用用户选定原设计，不改变各自实体安装边界。
- 马用驮箱、驴驮架、骡驮袋、骆驼商旅架和炽足兽驮袋必须有与局部点击区域一致的可见模型。
- 资源缺失时使用明确的开发占位纹理，正式验证门禁不允许紫黑缺失纹理。
- 所有 UI 文案使用翻译键，提供简体中文与英文；中文是目标整合包的首要校对语言。
- 物品纹理最终尺寸为 64×64，使用硬边像素、透明背景和 8–16 色的有限色板；概念图必须经过相近色合并、硬 Alpha 与物品栏尺寸可读性检查后才能作为正式资源。
- 管理页使用代码绘制的原版式面板和正式物品纹理，不额外依赖高分辨率 GUI 背景。
- 创造模式注册两个分类页：装备页枚举物品与货运拴桩；附魔页从动态附魔注册表读取本命名空间并生成最高等级附魔书。
- Jade 兼容为 `compileOnly` 软依赖：服务端数据提供者只发送已缔结标记、主人显示名与模式，客户端组件只在 Jade 存在时注册。

## 13. 配方、交易与战利品

- 常规配方使用 data JSON。
- 两条傀儡补强和冲角的保留组件升级共用一个最小自定义 recipe serializer。
- 保留组件 serializer 必须接受正常损耗的装备、拒绝错误基础物品，并按已消耗耐久比例换算输出损耗；有内容货运容器的拒绝由对应容器配方单独处理。
- 附魔、附魔标签和互斥尽量使用 1.21 数据驱动资源。
- 渔夫/牧师交易通过可选的数据/事件注入，不替换职业完整交易表。
- 交易价格、次数和战利品权重集中在数据层，不散落在实体行为代码。

## 14. 数据迁移与故障恢复

### 14.1 版本策略

- 每个组件独立 schemaVersion，从 1 开始。
- 新增可选字段必须有默认值。
- 改变容量时，先读取旧容量，再把超出物品放入恢复队列。
- 改名物品 ID 时提供 missing-mapping 迁移，不能让已装备物品消失。
- 原型期四件共用补强 ID 保留为隐藏迁移项；已装备旧物品按所在傀儡物种与原材料等级转成对应新物品，并保留组件、附魔和损耗。

### 14.2 异常数据

- 名单引用不存在实体：保留条目，UI 标记“当前未找到”，不按名字误匹配其他实体。
- 主人 UUID 无法解析：保持归属记录但禁用管理，允许以后恢复。
- 装备位出现非法物品：不应用效果；下次主人打开页面时移入背包，否则安全掉落。
- 链接拴桩的实体卸载：能力立即为空，区块重新加载后重新发现，不缓存跨加载实体对象。

## 15. 性能预算

首轮目标，不是微优化承诺：

- 100 只启用名单的伙伴平均分散扫描，不能形成明显 10 tick 尖峰。
- 无名单、等待和卸载实体不执行邻域扫描。
- 名单判断不遍历 256 条列表；使用加载后的 UUID/注册 ID 集合。
- 拴桩只在邻接查询、定期低频验证或实体/牵绳状态变化时刷新，不每 tick 枚举大范围实体。
- 客户端不持续发送按键或装备状态网络包。

## 17. 实现前风险验证

正式批量开发前先做六个最小技术探针：

1. Alt 请求是否能只拦截合法实体，同时 Shift + 右击仍由 Carry On 处理。
2. 不替换 Horseman 菜单时，能否安全让马鞍位接受驮箱并拒绝骑乘。
3. 实体局部点击在马、骆驼不同朝向和尺寸下是否稳定。
4. 拴桩代理能否被 Create 机械臂发现，并在断链竞态中不复制物品。
5. 美西螈带完整装备装桶再放出能否无损往返。
6. 狐狸受控近战能否禁用伤害附魔，同时保留击退、抢夺、耐久和经验修补。

任何探针失败都先修改架构或缩小功能，不在失败路径上叠加更多补丁。
